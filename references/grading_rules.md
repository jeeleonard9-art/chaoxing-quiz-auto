# 超星判分行为与作答通用规律

以下是与具体课程无关的**通用技术规律**，在推导 `answers.json` 时应直接套用。
（仓库不收录任何真实课程的题目或答案；示例中的名称均为占位写法。）

## 1. 填空题：空白不敏感，但文本内容必须一致

判分前，标识符与括号之间的**空白、全半角括号**会被归一化：

| 平台标准答案 | 你的答案 | 结果 |
|---|---|---|
| `init ()` | `init()` | ✅ 满分 |
| `getWriter ()` | `getWriter` | ✅ 满分 |
| `service ()` | `service()` | ✅ 满分 |

但**答案文本本身必须与标准答案一致**。判定用的是「归一化后**相等**」而不是「包含」：

| 平台标准答案 | 你的答案 | 结果 |
|---|---|---|
| `转发(forward)` | `转发` | ❌ 0 分 |
| `重定向(redirect)` | `重定向` | ❌ 0 分 |

也就是说，**中文术语 + 英文括注**是标准答案的常见写法，只写中文会被判错。
当题目同时给出中文与英文两种说法时，**按中文+英文括注的形式写**最稳妥。

## 2. 同一空里的多个答案点：命中任一点即算对

平台会把同一空的多个答案点写进标准答案文本，用 `;` / `;` / `,` / `、` 分隔：

| 平台标准答案 | 你的答案 | 结果 |
|---|---|---|
| `sendRedirect ();其他 Web 应用` | `sendRedirect` | ✅ 满分（命中其中一点） |
| `getContextPath ();getRealPath ()` | `getContextPath、getRealPath` | ✅ 满分（逐点命中） |

所以填空题写**多个点**时，用 `、` 或 `;` 分隔即可；只要每个点都能在标准答案里
找到一个归一化后相同的点，就算对。

## 3. 平台空位数可能少于题干中的下划线数量

`input[name=tiankongsize<qid>]` 是平台**实际创建的空位数量**，它可能少于题干里
`____` 的个数（出题与配置不同步时会出现）。

处理办法：**把多个答案用 `、` 连写放进同一个空位**。
`answer_work.js` 的 `distribute()` 会自动完成这个合并——答案数组长度大于空位数时，
多余部分自动并入最后一个空位。

反过来，若答案数组长度**少于**空位数，多出来的空位会留空，提交时会被完整性自检拦下。

## 4. 题干里的尖括号标签可能被服务端吞掉

形如 `<xxx>` 的内容会在服务端 HTML 里被删掉，题干会出现空缺：

| 题干里看到的 | 原可能是 |
|---|---|
| 「在配置文件里，**标签**用于指定访问路径」 | 某个映射类标签 |
| 「可替代配置文件中的**和**标签配置」 | 两个并列标签 |

还原方式：

1. 看**同一套题**里其它题干对同类标签的写法，保持一致（同一份题通常风格统一）；
2. 用该标签在技术上的常见用途反推；
3. 若某道单选题出现"两个都成立"的选项，说明被吞掉的标签正是区分点——
   选那个在技术事实层面**成立**的表述作为正确项。

`extract_questions.js` 对这类题干会给出 `[提示]`，提醒你回头核对。

## 5. 单选题必须只有唯一正确项

出题时通常保证有且只有一个正确选项。若推理过程中发现两个选项都成立，
多半是被吞掉的标签在起作用，按第 4 条还原后再判断。

## 6. 客观题在页面上的取值约定

| 题型 | 平台 `answertype` | 选项的 `data` 值 | `answers.json` 写法 |
|---|---|---|---|
| 单选 | 0 | `A` / `B` / `C` / `D`… | `"C"` |
| 多选 | 1 | `A` / `B` / `C`… | `"ABD"`（字母连写） |
| 判断 | 3 | `true`（对）/ `false`（错） | `"true"` / `"false"` |

## 7. 其它注意

- 作答时**不要用 JS 直接赋值隐藏域**：平台的 `addChoice()` 才是正解
  （同时维护 `check_answer` 样式与 aria 属性）。
- 填空题不要只用 `setContent` 写值：**必须 `sync()`**，
  否则提交接口序列化的 `textarea` 里是空的。
- 提交按钮与「暂时保存」按钮在同一行右侧；提交会弹二次确认框，
  框内 `#popok` 是确认键、`#popno` 是取消键。
- 提交是**不可逆的最终结果**，提交后不做任何复盘。
